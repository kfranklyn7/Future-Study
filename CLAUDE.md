# Future-Study

Hackathon project: map Brooklyn College Computer and Information Science (CISC) courses
to career paths and free learning resources. We're going for the MLH "Best Use of
Snowflake" prize, so core features should run on Snowflake (tables + Cortex AI).

## Current state

Data pipeline, Snowflake AI enrichment, Go API (`backend/`) and React app (`frontend/`) are in
place. See README.md for setup and the API. App data lives in `CISC.CORE` (the older
`CISC.PUBLIC` tables, some with quoted names like `"Course Requisites"`, are not used).
AI output (`COURSE_AI`, `PROGRAM_AI`, `COURSE_CAREERS`, `CAREER_CANON`, `RESOURCES`) is
precomputed by `snowflake/ai_enrichment.sql`; only `/api/recommend` calls Cortex live.

- `scrape_brooklyn_cis.py`: the main scraper. Pulls CIS programs, the course inventory,
  undergraduate and graduate bulletin PDFs, department schedules, syllabi, related PDFs and
  degree maps from brooklyn.edu, then writes one CSV per table to `data/csv/`.
- `scrape_rmp.py`: pulls Rate My Professors ratings for Brooklyn College professors
  whose course tags match a course in `course_offerings.csv`, writes `rmp_professors.csv`.
- `scraper/`: a separate, smaller course catalog scraper (`scrape_courses.py`) with its
  own README and requirements.
- `frontend/`: the web app (see Frontend below).
- `backend/`: Go API over `CISC.CORE` (see Backend below); also serves `frontend/dist`.
- `snowflake/`: load CSVs into Snowflake and run the Cortex AI enrichment (see README.md).
- `data/csv/`: scraped output, ready to load into Snowflake. `manifest.csv` lists every
  table with row counts and a description.
- `data.py`: quick pandas exploration of `data/csv/courses.csv`.
- `future_study.ipynb`: empty notebook.
- `ideas.md`: feature ideas (career paths, degree-map graph, interest-based search,
  professor ratings).

## Running the scraper

```powershell
pip install -r requirements.txt
python scrape_brooklyn_cis.py                      # defaults: --years 5 --output data/csv
python scrape_brooklyn_cis.py --years 5 --output data/csv --cache data/cache/pdfs
```

- "Recently offered" means listed as active in a bulletin, or on the department schedule,
  within the last `--years` academic years (fall through spring). In Nov 2026 the default
  window is 2022-2023 through 2026-2027.
- PDFs are cached in `data/cache/pdfs`. Don't commit the cache.
- Be polite to brooklyn.edu: keep the request pause in place and reuse the cache.

## Rate My Professors scraper

```powershell
python scrape_rmp.py              # about 38 requests, ~1 minute
```

- Uses the GraphQL endpoint RMP's own site calls (Brooklyn College is `School-223`). It is
  undocumented and can change without notice. RMP's Terms of Use prohibit scraping, so keep
  pulls infrequent.
- Raw responses are cached in `data/cache/rmp`, and a rerun reuses them. Delete that folder
  to pull fresh data. Don't commit it.
- `courses_taught` comes from the course tags students choose on RMP, not the college
  schedule. Tags in the old CIS numbering (`CIS15`, `CIS22`) mostly don't match yet.
- Star counts can differ from `num_ratings` by one or two; both come straight from RMP.

## Frontend (`frontend/`)

React 19 + TypeScript, Vite 8, TanStack Router (file-based routing), Tailwind CSS 4, and
React Flow (`@xyflow/react`) for graphs.

```powershell
cd frontend
npm install        # once after cloning, and again whenever package.json changes
npm run dev        # http://localhost:3000
```

- Routes are files in `frontend/src/routes/`: `index.tsx` (`/`, the BS in Computer Science
  course map, built in `src/components/map/` from `src/data/csMap.ts` and `courses.json`;
  rebuild the JSON with `python frontend/scripts/build_map_data.py`), `discover.tsx`
  (`/discover`, interest-based recommendations), `courses/` (list and `$code` detail),
  `programs/` (list and `$id` detail), `graph.tsx` (`/graph`, full prerequisite graph laid
  out with dagre), `careers.tsx`, `map.tsx` (redirects old `/map` links to `/`), and
  `__root.tsx` (layout and nav). Shared bits are in `src/components.tsx`, API calls and
  types in `src/api.ts`.
- Styling is Tailwind only. `src/styles.css` is the one stylesheet: theme colors
  (`accent` is Brooklyn College maroon) and a few shared component classes (`btn`, `field`,
  `card`, `chip`, `link`, `tag`). Don't add plain unlayered CSS rules on bare elements;
  they override every Tailwind class. React Flow's CSS outranks Tailwind, so style its
  nodes with inline styles, and pass `style={{ colorScheme: 'light' }}` to `<ReactFlow>`
  or it turns dark when the OS is in dark mode.
- `npm run dev` proxies `/api` to the Go backend on port 8001, so run `PORT=8001 go run .`
  in `backend/` alongside it.
  `src/routeTree.gen.ts` is generated by the router plugin; don't edit it by hand.
- Import from `src` with the `#/` alias (for example `#/components/Foo`).
- Install packages from inside `frontend/` so they land in `frontend/package.json`, and
  commit `package.json` and `package-lock.json` together. The repo root has a stray
  `package.json` from an `npm install` run in the wrong folder; the frontend doesn't use it.
- `node_modules/` is ignored by `frontend/.gitignore`; never commit it.

## Backend (`backend/`)

Go (`net/http` + `gosnowflake`). Reads Snowflake credentials from env vars
(`SNOWFLAKE_ACCOUNT`, `SNOWFLAKE_USER`, `SNOWFLAKE_PASSWORD`, `SNOWFLAKE_WAREHOUSE`,
`SNOWFLAKE_ROLE`); never put them in files. `go run .` serves the API and the built
frontend on http://localhost:8000. Endpoints are listed in README.md.

## Data model (`data/csv/`)

Course codes are written `CISC 3130` (dept, space, number; numbers can carry a suffix
such as `2820W` or `7100X`).

| Table | What it holds |
|---|---|
| `programs.csv` | CIS undergrad, grad and minor programs (`program_id` is the key) |
| `program_sections.csv` | Overview and requirement text per program |
| `program_courses.csv` | CISC courses mentioned in each program's requirements |
| `courses.csv` | Every CISC course found (`course_code` is the key) |
| `courses_offered_recent.csv` | Subset of `courses.csv` offered in the recent window |
| `course_requisites.csv` | Prerequisite and corequisite edges; use for the prerequisite graph. Records every course mentioned, not the and/or logic, so show the raw `prerequisites` text when the exact rule matters |
| `bulletins.csv` / `bulletin_courses.csv` | Bulletin PDFs parsed, and course entries in each |
| `course_offerings.csv` | Department schedule rows by term |
| `syllabi.csv` | Full syllabus text per course (good input for Cortex) |
| `related_documents.csv` | Other linked PDFs (prereq diagrams, checklists) |
| `degree_map_courses.csv` | Four-year degree maps by program and bulletin year |

CSVs are written without a pandas index column, so they load into Snowflake directly.

## Snowflake

- The team's data lives in a shared Snowflake account owned by Kevon. Teammates are invited
  as users.
- Objects created while using ACCOUNTADMIN are invisible to SYSADMIN. If a teammate can't
  see a database, check its owner with `SHOW DATABASES;` and grant access, or create
  objects as SYSADMIN in the first place.
- Set a default warehouse before running queries.
- For LLM features, use Cortex `AI_COMPLETE`. Check which models the account has with
  `SHOW CORTEX BASE MODELS;` (Claude Opus 5.5 is `claude-opus-5-5`, in preview and not in
  every region).
- Never commit credentials. There is no `.gitignore`, so keep any `.env` or connection
  file out of commits by hand.
